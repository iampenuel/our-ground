# Private correction operations

Penuel checks the restricted queue and monitored mailbox every day at 9 a.m. and 6 p.m. Eastern. Forms enter PostgreSQL. Use the original restricted reviewer CLI from the workspace to inspect oldest open cases. Confirm the publisher evidence before suppressing a real location. Penuel alone is responsible for recovery. The private key is a separate personal Apple Passwords entry named **Our Ground — Private corrections recovery**, user name **private-corrections-20261108**. The established production directory passphrase and checkpoint are independent.

The operator runs the helpers with the existing application workspace available at `/Users/admin/Documents/Projects/our-ground` on this Mac. The service uses its existing owner/reviewer connection files and TLS certificate. No credential or report content belongs in a terminal command, receipt, screenshot or application log.

1. Run `python3 backup.py init-key` once and `python3 backup.py backup`. The first command refuses to create a missing key when a private archive already exists. Place only the new passphrase in the Masked Password field of the *personal* vault entry. Clear the transfer clipboard. Copy the password afresh from the saved entry, then run `python3 backup.py verify-vault` in Terminal and paste into its hidden prompt. A successful test decrypts the actual external archive to a discard stream using an empty GnuPG home.
2. Run `/usr/bin/python3 install.py` to register the local user's LaunchAgent. It executes at 6:15 p.m. local time with hourly catch-up, including on login and after wake. The operator keeps the Mac available and Penuel Back mounted/unlocked near the evening run. A logged-out, sleeping or disconnected workstation can miss a backup. See the last verified receipt and scheduler status under the workspace's private `tmp/adult-release/corrections` directory. Use `launchctl print gui/$(id -u)/org.ourground.private-corrections` to check the registered job.
3. After monitoring and vault custody are ready, `python3 availability.py resume` opens intake against a verified snapshot. `python3 availability.py status` reports coverage, intake and remaining seconds. Before an absence exceeding one day, run `python3 availability.py pause`. This sticky owner choice stops new submissions immediately and remains effective across successful nightly jobs. Resume after reviewing the queue/inbox and confirming availability.
4. On a failed backup/restore the job deletes the intake lease. Even if the workstation cannot reach Redis, the lease expires 24 hours after **the source snapshot**. Recover the drive/permissions and run `python3 availability.py nightly`. After an absence, only an explicit `resume` clears the sticky pause.
5. The directory checkpoint and its SHA-256 are pinned in `backup.py`. Private files sit in `/Volumes/Penuel Back/Our Ground Backups/private-corrections/YYYY-MM-DD.dump.gpg`. Each successful day atomically publishes one encrypted file and prunes completed daily files beyond 30. A retry replaces only that day's verified ciphertext after isolated restore. The restore pairs the directory base with five allowlisted tables: correction reports, review events, operational location holds, source privacy holds and source privacy events. No auth users, grants, secrets, claim data, images or account records are exported.
6. Every backup uses PostgreSQL's exported consistent snapshot, streamed AES-256 encryption, and an actual restore into a fresh Unix-socket-only PostgreSQL instance. It compares row fingerprints, published IDs, restricted ACLs, and source holds before declaring success. The instance, data and write-ahead logs are removed after verification. Never restore into the live database directly. For a past checkpoint, use the same versioned directory base plus its archived private file with both matching passphrases in an isolated database. Inspect the recovered queue and suppression history before any separately authorized recovery switch.
7. The helper refuses completion if the directory checkpoint no longer reconstructs the published identities or if records in the separately governed retention-hold table need a wider custody plan. Refresh the verified directory baseline after directory changes, review any hold-preservation requirements before the 30-day rotation, and keep intake paused until restore matches. The 30 daily archive limit does not set the database's report deletion policy.
