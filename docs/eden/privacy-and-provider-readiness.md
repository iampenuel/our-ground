## Audit method and evidence limits

Inspected the current working tree, including existing uncommitted work. No production console, live database, provider account settings, billing account or hosting logs were inspected. Secret-bearing `.env.local` contents were not read. No live model or speech request was made, and no resident data was submitted to an AI provider. Public documentation retrieval is distinct from API inference.

Status vocabulary:

- **Implemented locally:** observable code/configuration; not proof it is deployed or correctly configured on a host.
- **Locally tested:** the named offline tests actually ran during this audit.
- **Proposed:** architecture or release requirement; no implementation claim.
- **Unverified:** requires hosted evidence, provider/account confirmation, or legal/operational review.

Earlier planning in `docs/architecture/maps-ai-readiness.md` and `google-maps-gemini-plan.md` is historical. Its prospective Gemini endpoint and older geographic/map assumptions must not be read as current approval. This EDEN-02 assessment governs the proposed assistant's privacy/provider decision without rewriting those records.

## Data classification and default handling — proposed

Treat identifiability, small-area location and combinations as relevant; removing a name does not necessarily anonymize a request.

| Class | Examples | Proposed EDEN handling |
| --- | --- | --- |
| P0 — approved public facts | Published listing hours, category, provenance, public page enum | Only server-validated, bounded projections may enter optional provider context. Public business contacts/links can be rendered directly without sending them to a model. |
| P1 — linkable operations/context | Random session/request handle, city/ZIP, language, device/IP bucket, selected result | Minimize and separate purposes. Keep geography/search center inside the deterministic search service by default; do not send it to an LLM merely because it is coarse. HMAC is pseudonymization, not anonymization. |
| P2 — sensitive resident information | Diagnoses, disability, mental/reproductive health, benefit/financial hardship, housing insecurity, immigration status, exact address/GPS, voice/background speech, identifiable minors' data | Initial remote-AI envelope excludes it. Keep input local, discard on clear/timeout, and offer category/city controls. Any future processing needs a separately approved use case, audience eligibility, notices, legal basis and processor terms. |
| P3 — secrets/private workflows | Access/refresh tokens, auth codes, credentials, private claims/review notes, donation/payment data, identity documents | Never collect into EDEN context or provider payloads. No account/admin/donation/form tools. No attachment upload. |

Automated redaction/classification is supplementary. It can miss a diagnosis, inferable location, another person's name, a child's voice or a secret. The primary controls are finite structured inputs, route/capability separation, default exclusion, explicit payload schemas and failure to deterministic assistance. A remote classifier/moderation/STT service is itself a disclosure recipient and requires the same approval; it is not a pre-consent sanitization escape hatch.

## Recommended privacy experience — proposed

Start with public category buttons, supported city/ZIP selection, search explanation templates and the existing accessible text interface. Never require an account, birth date, government ID, microphone, parental contact or AI consent to access public resources. Unknown-age users retain this path. Provider selection/age checks must not gate the directory itself.

Before any optional AI transfer, disclose the named processor, exact categories sent, purpose, provider retention/review conditions, and an equally usable “Continue without AI” choice. No prechecked opt-in, implied permission from searching, or generic privacy-policy checkbox. For a structured model-assisted feature, show the derived intent before sending it. Keep an easily reached Clear session and Stop action; no chat persistence across refresh by default. A model session must not be joined to an organization login.

Remote voice is a separate later gate. First explain processing and retention, then accept an explicit microphone action, then request the browser's permission. A browser permission alone is not consent to a particular provider/use. Use push-to-talk, a visible recording indicator, a 30-second turn ceiling, no pre-roll/background listening or camera, stop all tracks on stop/navigation/timeout, and discard buffers. Voice can contain bystanders and protected information before redaction is possible. Existing `microphone=()` and `media-src 'none'` remain intact during this audit. Do not assume browser speech recognition or synthesis is entirely on-device.

Accessible text statuses must remain independent of the Rive animation. Offer keyboard controls, reduced motion, transcripts/captions for any future audio, silence/mute, screen-reader announcements only for state changes, and equal functionality when voice/animation/provider access fails.

## Retention and deletion — proposed EDEN policy, not activated

| Data/purpose | Proposed default | Deletion/control |
| --- | --- | --- |
| Raw conversation, audio and transcript storage | **No application persistence.** Bounded in-memory turn buffers only; clear at turn end for audio, session clear/navigation for text; five-minute inactivity timeout and 15-minute session maximum. | Cancel streams, stop tracks, release references. This does not promise forensic erasure of browser/OS memory or deletion of already transmitted provider content. |
| Model context | Current approved structured intent + at most five public result projections; no remote conversation memory/files/vector store by default | Drop request buffers after completion/failure. Rebuild only from current authorized state. |
| Exact search location | Existing search service only, transient selected location; not an assistant transcript or AI payload | Do not create a new location history. Apply current public-area cache rules rather than caching exact personal positions. |
| Operational events | Seven days, metadata allowlist only: random request ID, route enum, outcome, timing/usage buckets, policy/model version and cost reservation | Restricted operator access; automatic TTL must be tested before real traffic. No raw prompt/output, audio, IP, URL/query, contact, account ID, listing+resident joins or exception objects. |
| Abuse counters | Rotating keyed network/session buckets; ≤24 hours per bucket plus expiry margin | Separate key/namespace from account identity; no cross-purpose linking. Global counters contain only counts. |
| Spend reservations | Per-request record ≤7 days; global day/month counters ≤35 days; longer accounting only aggregate, no resident identifiers/content | Reconcile/expire atomically. Do not keep conversations as billing evidence. |
| Incidents/legal holds | Separately authorized, narrow, documented and access-controlled | Do not silently turn on transcript capture. Counsel sets legal hold scope and notification duties. Preserve necessary security metadata, minimize resident content. |
| Providers/hosting/backups | **Unverified and potentially different from Our Ground policy** | Contract/configuration-specific retention, deletion exceptions, location and backup ageing must be recorded before release. “Clear” cannot revoke past disclosure. |

Existing organization records retain their separate 90/180/365-day policy and holds; this proposal does not change it. No destructive batch, scheduler or database policy was modified.
