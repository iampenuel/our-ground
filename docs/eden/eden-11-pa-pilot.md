# EDEN-11 · Pennsylvania directory acceptance

**GO for protected reviewer use. NO-GO for public production.** On November 7, 2026, the existing [Vercel Preview](https://ourground-staging-git-eden10-penuels-projects-aa802b06.vercel.app) served **367 real Pennsylvania listings: 324 food and 43 healthcare**. All were labeled imported and not independently verified. The same deployed application and restricted Supabase role served the new directory without a rebuild, deployment, migration, production configuration change, or provider activation.

## EDEN acceptance

Mocked, allowlisted function proposals exercised the deployed navigation and page-action code. Home, Find Support, Give Support, For Organizations and About each returned their own page facts. The city, category and radius survived navigation away from Find Support and back. Search, radius and category changes, reading loaded titles, opening a selected record and focusing a marker operated on actual published results. A stale action was rejected. No account, donation or submission operation was granted. These checks establish controller behavior; they do not establish hosted model inference, a voice session or a general conversational memory. Hosted text, speech and Live endpoints remained disabled (403). Local Gemini/Aoede and the approved character were unchanged.

To repeat the checks on this exact deployment, use Node 24 and Chrome on macOS. From the repository root, point `EDEN11_STAGING_LINK` at the existing **staging-linked directory** with a current Vercel development OIDC token in its private Preview env file. Run `node scripts/eden/check-pa-preview.mjs desktop` or `mobile`. The [runner](../../scripts/eden/check-pa-preview.mjs) checks the staging project and sends the authentication header only to the approved origin. The [scenario](../../scripts/eden/pa-preview-scenario.js) pins this artifact’s module names; a different deployment or dataset needs its own review. Reports go to a fresh ignored directory; the runner does not update the database or request a Gemini session.

## Reliability and recovery

- The original protected Preview remains READY. Anonymous home/API requests redirected to Vercel sign-in (302); authenticated health returned 200. The project still has 20 Preview-only settings, no Production settings, and the same Preview alias. [Protection evidence](verification/eden-11/protection.json) · [anonymous requests](verification/eden-11/anonymous-alias.json).
- Database size was **66,574,003 bytes before**, **68,277,939 bytes after final verification** (~13.7% of [500 MB Supabase Free allowance](https://supabase.com/pricing)). Application indexes measured 32,858,112 bytes; limiter storage 65,536 bytes. Thirteen restricted-role search samples measured **0.46–19.82 ms** on PostgreSQL, with warm data, excluding connection and browser time. No sustained-load or uptime claim. [Final measurement](verification/eden-11/final.json).
- The runtime role could execute limiter admission but could not read raw services or the limiter table. Eight parallel hosted city submissions returned six 200 and two 429, with 58-second Retry-After; the action recovered. Three recent cleanup runs succeeded. The unchanged binary’s [EDEN-10 storage-failure check](verification/eden-10/hosted-verification.json) returned 503 and recovered when the lock was released; no forced outage was repeated. [Current limiter result](verification/eden-11/limiter.json).
- In a bounded log check, 100 Preview request records showed 97 HTTP 200 and 3 HTTP 304; no runtime entries or credential signatures were found in that sample. The platform still records request metadata including path, country and user agent. The sample does not establish platform-wide redaction or retention. Raw logs were not copied into the repository. [Log evidence](verification/eden-11/log-check.json).
- Both the prior restore-tested three-record checkpoint and a **new encrypted external checkpoint of the corrected 367-record directory** passed digest verification after decryption from Penuel Back. No file was overwritten. All compressed members were read; offline archive counts were 367 services, 367 source bindings, 32,415 geographic records, 15 migrations and zero resource privacy holds. [Final archive and path](verification/eden-11/final-recovery.json) · [archive comparison](verification/eden-11/archive-audit.json). The new archive is not a newly tested database restore. It contains the directory, migration journal and limiter schema; private workflow data, managed Auth, passwords, ephemeral buckets and the cron catalog are outside its scope.
- For rollback, use an **empty, separately identified recovery target** and the [recovery procedure](eden-08-manual-recovery.md). Never restore over the serving DB. Preserve newer corrections or withdrawals before switching. Provision the prerequisite extensions and roles, including the non-login limiter owner for the final archive; restore ACLs, then register the reviewed purge job without recreating the restored limiter schema. The earlier three-record archive instead needs the complete staging limiter overlay. Verify public counts/IDs, source links, raw-table denial, search, protection and rate limiting on the recovery target before any separately approved Preview cutover. Keep the decryption key recoverable separately from the ciphertext. Cross-project restoration and independent key escrow remain unverified.

**Before public release:** Assign a directory steward and refresh/withdrawal cadence, review a reusable PA food source outside Philadelphia, verify a disaster restore with recoverable keys, and set production capacity, monitoring, privacy/log retention and map-abuse controls. The accepted headerless browser-key quota exposure remains limited to this staging review. Public Gemini and voice require their own audience, eligibility, consent and operational decisions. None of those gates was relaxed.
