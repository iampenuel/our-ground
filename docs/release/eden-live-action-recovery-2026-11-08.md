## Cursor authority and lifecycle

[Official component](https://reactdrops.dev/components/cursor/showcase-pointer), [source repository](https://github.com/crisjavr/reactdrops). Installed using the requested shadcn registry command in an isolated setup directory, then inspected and incorporated into the app as a small React island. The original component and motion sources, including their license, are under `src/eden/reactdrops`. The Our Ground extensions add AbortSignal cancellation and an immediate visual stop to imperative movement. React, ReactDOM, GSAP and the component's React integration are pinned in the lockfile.

There is one pointer, labeled **EDEN**, colored `#171717`, in a pointer-transparent fixed overlay. No scripts loop and no second character is configured. Real HTMLElement targets are resolved afresh from the owned public-control registry; no model selector, URL, JavaScript, password, private input or account form is accepted. Curved minimum-jerk movement, the original visual hover/press/selection attributes and component capabilities are retained. The live adapter never calls the component's typing or drag mutation helpers.

For a validated action the coordinator resolves and checks the target, presents the appropriate motion/press, re-resolves it to reject stale/disabled/hidden controls, then invokes the existing application engine. A visual press callback is never an executor. Search values are applied by that engine, not by the cursor component. The engine confirms the resulting search, selected record or view before the conversation reports success. Scrolling has no fake press. A route change resolves new controls; trusted user input, cancellation and document hiding interrupt the sequence. Failed rendering does not disable an otherwise valid operation. Reduced motion uses a nonmoving action status, and the overlay never intercepts input or changes the OS cursor. The visual island is hidden and disposed when idle.

Local `eden:visible-action` events contain an operation ID, the turn correlation ID, finite target capability, operation phase and target rectangle. The turn diagnostic identifies provider, model, proposed action, confirmed/failed outcome and response provenance. Both omit raw visitor input, private fields, credentials and hidden reasoning. Debug output is opt-in; no new external telemetry is sent.
