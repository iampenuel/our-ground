## Enforced CSP and build separation

`shared/security-headers.ts` emits **Content-Security-Policy**, not report-only. Scripts/styles/fonts/manifests are self-only, script/style attributes denied; frames/plugins/media denied. MapLibre workers use self/blob and images self/data/blob plus exact `https://maps.geoapify.com`; connect permits self, `https://api.geoapify.com`, `https://maps.geoapify.com` and one validated configured HTTPS Supabase origin. No unused Google/Mapbox host, wildcard Supabase, unrestricted socket, inline/eval/wasm exception exists in production policy. Google OAuth uses top-level navigation, not external scripts/iframes.

Browser/server Auth configuration must agree. Canonical project validation rejects arbitrary domains/paths/ports/credentials/header injection. Unconfigured builds permit no Auth host. Explicit local fixture Auth can allow only its isolated loopback target; dev HMR exceptions are local-only and absent from compiled/hosted policy. Installed MapLibre 6.16.0 does not require wasm/eval/style-attribute exceptions. See [MapLibre CSP](https://maplibre.org/maplibre-gl-js/docs/#csp-directives), [style-src-attr](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/style-src-attr), [script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src).

Committed `vercel.json` is strict/unconfigured; the renderer creates a separate exact manifest-host candidate, refuses overwrite and never embeds keys. The preflight compares configured Auth origin with that candidate's headers/private rules. Vite now writes a public-config fingerprint plus actual asset hashes after bundle output. Preflight verifies the explicitly selected `--build-dir` against that evidence and exact environment/Auth/CSP configuration, rejecting stale/modified/fixture bundles. The current actual build passed with 70 hashed assets. This is accidental-stale-artifact protection, not a cryptographic signature or deployment authorization. The guard also checks runtime warning thresholds and rejects an unsupported separate location-budget variable rather than inventing an independent provider allowance. No local test grants deployment permission.
